# 0073 — HLOD: proxies for streamed and authored cells

- **Status:** accepted. Part 1 (runtime proxies for streamed cells, region meshes) built;
  implemented once its criteria pass in CI. Part 2 (offline proxies for file cells) waits on 0072's
  importer.
- **Packages:** `@aethervtt/shard-hlod` (new), `@aethervtt/shard-render`, `@aethervtt/shard-structure`,
  `@aethervtt/shard-partition`, `@aethervtt/shard-mesh`, `@aethervtt/shard-procgen`, `apps/cli`
- **Depends on:** 0022, 0055, 0067, 0072, 0103, 0113, 0116

## Context

0113 streams a town as generated cells: `full` near a player, `far` shells (outer walls, doors,
windows, roofs, ground) out to the last ring. Risen draws 16 full and ~84 far cells, and its frame
is over budget. Measured on an Apple M5 Max (headless Chromium, 1920×1080, CPU-bound, 2026-11-13;
GPU untimed):

| | Mesh slots | Camera draws | CPU ms |
|---|---|---|---|
| Whole frame | 18,736 (16,650 distinct batches) | 3,391 | 16.5 (p95 17.2) |
| Full ring houses (16 cells) | 5,053 | 1,075 | 2.9–4.9 |
| Far ring houses (80 cells) | 4,158 | 247 | 2.5–2.6 |
| Ground (structure's global group, 8 m chunks, all cells) | 8,107 | 2,057 | 2.8–4.6 |
| Everything hidden | 18,724 hidden | 12 | 6.5 |

Three things follow:

- **Slots cost, drawn or not.** Hiding everything leaves 6.5 ms of queueing, uploads and instance
  preparation. A proxy must remove its cell's slots, not hide them.
- **Structure has no LOD, and every chunk is its own batch.** Far shells draw at full detail as
  thousands of 8 m chunks per material, the ground most of all.
- **Occlusion doesn't pay yet.** It halves camera draws, but costs more than it saves over 16.6k
  single-instance batches: the frame goes from 16.5 to 18.4 ms.

Baking offline from 0072's cell files can't serve this alone. Cells are generated on each client,
they change while loaded, and what draws is added after commit by game code (Risen's client dresses
cells with meshes and runtime materials, since fragments carry no render handles). So this spec
builds proxies on the client, from what it draws, while it runs. Authored file cells also get
proxies built offline by the same build, cached, and optionally `baked` into one textured mesh.

## Goals

- A proxy per cell of a `proxy` level, built at runtime on the worker pool from what the cell draws
  once committed and dressed, under a per-frame main-thread budget, never stalling a frame.
- Structure (walls, openings, frames, door leaves, roofs, floors) in the proxy, with LODs inside it.
- Rebuilt when the cell's delta or dressing changes, and only that proxy. A stale proxy draws until
  its replacement lands.
- One swap distance: a cell ↔ its proxy at the level swap, where only windows change. Proxy windows
  are dark.
- Exact coverage on every frame: each cell's area draws once, never zero or two times.
- Proxies cast into 0116's static layers and occlude like the cells they replace.
- Near structure merged per 32 m region for camera views, so the full ring costs regions, not chunks.
- Both tiers: correct on the WebGL2 baseline, if slower.
- File cells (0072, part 2): proxies built offline by `shard hlod build`, cached by content, loaded
  instead of built at runtime. The `merged` method, or `baked`: one simplified mesh with base
  colour, normal and ORM textures baked from the originals through the G-buffer, for any 0020
  material. Two builds give identical bytes.

## Non-goals

- Proxies for unloaded cells, past the last ring (see Open questions). Headless runs and servers
  build nothing: `hlodPlugin` needs `render/forward`.
- `baked` at runtime. See Decisions for the numbers.
- Terrain (0071), scatter (0045), lights and lit windows, characters (0115), crossfades.

## Design

### Levels, coverage and the swap

- A grid level with `proxy: true` (Risen's `far`) is drawn by proxies. Its cells still commit: they
  are the proxy's source and take deltas. `proxy` on the first level is `partition/bad-levels`.
- **Covered** means the cell root has `render/DrawnByProxy`. `ComputedVisibility` inherits it as
  `proxied`, over any mode below (`visible` included). A proxied mesh gives up its instance slot and
  reads as hidden, so its occluder occludes nothing. One write per cell, not per entity. Structure
  still compiles a covered cell: its meshes keep their CPU data, the next build's source.
- **Order within the frame:** `structure/compile`, transform propagation, `hlod/select`,
  `render/compute-visibility`, render's prepare (all PostUpdate). Covering, uncovering, showing and
  parking a proxy land in one frame.
- **Rules per cell, each frame:**
  - at a non-proxy level: uncovered. Its proxy, if any, is parked: it has `DrawnByProxy` itself
    (the cell draws in its place), so it holds no slots while it waits;
  - at a proxy level with a proxy: covered, and the proxy draws;
  - at a proxy level with no proxy yet (first sight): uncovered, so it draws as itself, and it's
    covered in the frame its proxy takes over;
  - a new proxy is committed parked and takes over the next frame, once transform propagation has
    placed it. Until then the old one (or the cell) draws.
- **One distance.** The swap is 0113's level swap (`full` range, with its hysteresis). A cell going
  back out covers in the swap frame with its parked proxy, then rebuilds if its far content differs.
  A cell seen at `far` for the first time draws its far shell until its proxy lands, a few frames;
  shell and proxy are the same triangles but for windows, which proxies draw dark
  (`HlodSettings.windowColor`), so missing interiors never show.
- **Ground per cell.** `hlodPlugin` sets `StructureSettings.groundGroups: 'root'`: a piece with no
  Level draws in a ground group under its root entity (the cell root) instead of the world's one
  ground group, so a cell's streets and grass go with it.

### Members

- **Included:** every entity under the cell root with `Mesh3d` and `MeshMaterial`: structure's
  chunk or region meshes, door leaves, contact shade, and the game's dressed meshes. Window panes go
  in as dark quads. A `Lod` member contributes its first level.
- **Excluded:** subtrees under `hlod/Exclude`, or whose own `Visibility` is `hidden` or
  `shadow-only`; skinned or morphed meshes, `DynamicCaster`, and structure's shadow proxies (the
  proxy makes its own).
- **Posing:** door leaves are merged at their current angle. A swinging door moves every frame, so
  the cell settles once it stops.
- **Settled:** a cell gathers once every member's mesh and material is loaded and no member changed
  for `settleFrames`.
- **CPU data required:** a mesh with no CPU data (`Mesh.gpu`) is left out with
  `hlod/mesh-unreadable` (a warning, once per mesh).

### Build

1. **Gather** (main thread, in `hlod/select`, `gatherMs` per frame, at least one cell): each
   member's attribute arrays, world matrix, material and casting, and each `Occluder`'s triangles;
   nearest cells first, `jobsInFlight` at most.
2. **Worker:** `buildProxy` from `@aethervtt/shard-mesh`, exported by procgen's worker module, the
   bundle every host already builds self-contained for its pool. Without a pool it runs inline.
   Members are merged per bin (a material, cast as itself or not) in world space, sorted by size,
   largest first; a mirrored member flips its windings. It returns the levels, a positions-only
   shadow mesh, occluder triangles per 32 m region (at most 256 each, the largest kept) and bounds.
3. **Commit** (main thread, `uploadBytes` per frame, at least one proxy): meshes in arena
   `'structure'`, and the proxy's entities, parked.

- **LODs by part size, not surface simplification.** Box-built geometry has a seam at every hard
  edge, and meshoptimizer keeps 99.5–100% of it (measured). A part is a member mesh. Level k keeps
  the parts whose bounds diameter is at least `pixelError` pixels (1080 rows, 60°) at 96 × 2^k m;
  members are sorted by size, so a level is a prefix of level 0's arrays. Up to `lodLevels`, a level
  that drops nothing is skipped, and each bin switches with 0022's `Lod` where its next drop is
  `pixelError` pixels (0103's rule). A bin whose parts all drop stops drawing there.
- **Proxy entities** (children of the partition root, `core/Derived`, never saved):
  - a root with `hlod/Proxy { grid, x, z, triangles, levels }`;
  - one `Mesh3d` child per bin, with `Lod` when it has levels, and `NotShadowCaster` unless its
    material casts as itself (masked, double-sided or custom types);
  - one shadow-only child for the shadow mesh;
  - one `Occluder` child per 32 m region the cell's occluders lie in.
- **Shadows.** The shadow mesh is every casting member of a plain standard, opaque, single-sided
  material: the same triangles the cell's structure gives 0116's shadow proxies, and its dressed
  meshes. Proxies are static casters, so a swap or rebuild is a rect redraw.
- **Occluders** come from the proxy for a covered cell and from structure's chunks for an uncovered
  one. Coverage picks exactly one source per cell, each frame.

### Rebuilds

A cell is dirty when one of its members (not skinned, morphed or a `DynamicCaster`) changes
`Mesh3d`, `MeshMaterial`, `GlobalTransform` or `Visibility`; when a `Mesh3d` or `Occluder` is added
or removed under its root; or when structure's compile report names one of its groups (chunks rebuilt
in place keep their `Mesh3d`). Deltas (`applyCellDelta`), redressing and level swaps all arrive this
way, so HLOD needs no hook per source. Only that cell's proxy rebuilds; its old one draws until the
replacement takes over.

### Near cells: region meshes (structure)

With `StructureSettings.cameraRegions` (default false; `hlodPlugin` turns it on), camera and shadow
views draw one merged mesh per (region, group, material) instead of each chunk mesh: 0116's shadow
proxy with every attribute, on the same grid (`shadowRegion`, or 32 m when that is 0).

- **Chunks** stay the unit of rebuild. Their entities lose `Mesh3d`, so they hold no slots, and keep
  their occluders.
- **Rebuilds:** an edit rebuilds its chunks, then their regions, in the same compile.
- **Casting** follows the chunks: a region casts as itself only for materials 0116's shadow proxies
  don't merge. `ShadowWhenHidden` and `Cutaway` carry over.
- **Door leaves** and contact shade stay as they are, and a door toggle still rebuilds nothing.

### File cells: offline proxies (part 2)

A file cell (0072) can get its proxy from the cache instead of a runtime build.

- **`shard hlod build [partition]`** opens each stale cell headless, with the project's plugins
  but no game client systems, gathers members as the runtime does (prefab and scene instances
  expanded) and runs the same `buildProxy`. Members are sorted by path, so two builds give
  identical bytes. A cell's record lives in `.shard/cache/hlod/<partition hash>/`: its meshes
  (0014's codec), its textures (KTX2), its bounds and its key, `sha256(the grid's hlod settings, the
  cell's member data (canonical), the artifact hashes of its meshes, materials and textures, the
  build version)`.
- **`shard dev`** rebuilds a record in the background after its cell is saved; **`shard export`**
  builds every record and fails with `hlod/missing` if one can't be built; **`shard hlod status`**
  lists stale cells and why.
- **At runtime** a file cell at a proxy level loads its record instead of gathering. If a runtime
  diff touches a member, the runtime rebuilds it as `merged`: a baked record can't follow a change.
- **`baked`**, per grid (`hlod: { method: 'baked', texelsPerMetre }`, file cells only): merge, then
  simplify with meshoptimizer's attribute-free simplifier to the error at the swap distance; unwrap
  with xatlas (WASM, `import()` by the build only); render the members with their own materials
  into G-buffers from 14 orthographic directions; blend the views that see each atlas texel by how
  directly they face it; write base colour, object-space normal and ORM, dilated by 4 texels. The
  proxy draws with an `hlod/Proxy` material. A grid set to `baked` with generated cells logs
  `hlod/baked-generated` and builds `merged`; with no GPU adapter, `baked` cells fail with
  `hlod/no-gpu`.

### API sketch

```ts
// @aethervtt/shard-hlod — client only, nothing registers on import
export function hlodPlugin(): Plugin   // needs render/forward, structure, partition
HlodSettings (resource) {
  enabled: bool = true, pixelError: f32 = 1.5, lodLevels: u8 = 3,
  jobsInFlight: u8 = 4, gatherMs: f32 = 0.5, uploadBytes: u32 = 4 << 20, settleFrames: u8 = 2,
  windowColor: vec3 = [0.02, 0.02, 0.025], occluderRegion: f32 = 32, occluderTriangles: u32 = 256 }
HlodProxy { grid: u8, x: i32, z: i32, triangles: u32, levels: u8 }   // hlod/Proxy, on proxy roots
export const Exclude: TagDef                                          // hlod/Exclude
Hlod (resource) { cells, built, jobs, ms, buildMs, paused }           // paused: freeze, to inspect
export function hlodSettled(world): Promise<void>                    // no build in flight
// partition: a level option (part 2: per grid, how file cells' proxies are built)
levels: [{ name: 'full', range: 96 }, { name: 'far', range: 320, proxy: true }]
hlod: { method: 'merged' | 'baked' = 'merged', texelsPerMetre: f32 = 4 }
// render
export const DrawnByProxy: TagDef                 // render/DrawnByProxy, inherited, no slots
ComputedVisibility { visible: bool, shadowOnly: bool, proxied: bool }
// structure
StructureSettings { ..., groundGroups: 'global' | 'root' = 'global', cameraRegions: bool = false }
StructureCameraRegion { group, x, z }             // structure/CameraRegion, on region meshes
// mesh: pure, run on the pool by procgen's worker module
export function buildProxy(input: ProxyInput): ProxyOutput
```

### What this asks of a game (Risen)

- **Turn it on, client only:** `app.addPlugin(hlodPlugin())` where `render/forward` is, and
  `proxy: true` on the `far` level of the town grid.
- **Exteriors:** the far level keeps everything visible from outside, as data: yard props' merged
  meshes, fences, porches, steps, and exterior `risen/Part` trim. Today `far` drops yard props, so
  the proxy would miss them.
- **Interiors:** nothing, while `far` holds none. `hlod/Exclude` is there for a level that does.
- **Dressing:** none. `Mesh3d` stays on dressed entities; coverage only drops their slots.
  Materials made at runtime are referenced, not copied.
- **Occlusion:** turn on `OcclusionCulling` on the camera once proxies land (today it slows the
  frame).
- **Breaking walls:** keep regenerating `risen/Part` meshes when walls change (Risen's ROADMAP step
  7). The proxy follows the `Dress` change.

### Agent surface

- `hlod.describe`: per level, cells loaded, covered, still drawn as shells, building and stale;
  proxies, their level-0 triangles, builds so far, jobs in flight and last frame's ms. MCP:
  `describe_hlod`.
- `hlod.cell { key }`: a cell's level, whether it's covered, its proxy's levels and triangles, and
  whether a build is in flight or it's stale.
- `Hlod.paused` freezes coverage and builds, so a ring can be taken out by hand (the town-hlod
  scenario's per-ring report does this).
- Not built: `hlod.describe { ablate }`, `hlod.preview`, `render.capture { debug: 'hlod' }`; part 2's
  `shard hlod build|status`, `preview_hlod`, `build_hlod`.
- Errors: `hlod/mesh-unreadable` and `hlod/build-failed` (warnings), `partition/bad-levels` (`proxy`
  on the first level); part 2: `hlod/baked-generated`, `hlod/no-gpu`, `hlod/missing`, `hlod/too-big`
  (an atlas over 4096² at its `texelsPerMetre`).

## Decisions

- **Rewritten in place, not superseded.** It was unbuilt, and five specs point at "HLOD (0073)".
- **Runtime proxies are `merged`; `baked` is offline only.**
  - `baked` at runtime would need xatlas and a texture encoder in the client. Shard has neither.
  - It would cost 14 G-buffer views per proxy on every rebuild.
  - Not popping at the 96 m swap needs about 10 texels/m (0.10 m per pixel at 1080p and 60°). For a
    far cell's ~4,850 m² that's a 1024² atlas: about 12 MB uncompressed per cell, about 1 GB for 80
    cells.
  - `merged` builds in 1–2 ms per cell (measured, As built) and reuses the materials.
- **Merge what's drawn, not structure's pieces again** (as built). Structure's compile needs the
  forward renderer, so it can't run on a worker; its chunk and region meshes are already the exact
  triangles, and a proxy of them matches the cell bit for bit.
- **Park proxies, don't prebuild from `full`** (as built). A parked proxy holds no slots, so it
  costs a cell's memory and nothing a frame, and covers the cell in the frame it goes back out. A
  far level seen for the first time draws as a shell for a few frames; that's the far level's own
  look, but for windows. Prebuilding would have needed every game to tag its interiors.
- **One build for both paths.** Offline and runtime proxies of the same content are the same bytes.
- **Builds run in procgen's worker module.** Every host already bundles it self-contained for its
  pool; a second bundle per host would buy nothing.
- **No `instances` method.** Repeated members are door leaves of 12 triangles. Merging them costs
  less than a batch each.
- **Cover, don't hide.** Hidden slots cost 6.5 ms for 18.7k of them (measured). `DrawnByProxy`
  removes the slots, and parking reuses the same tag.
- **Part-size LODs, as prefixes.** Structure geometry doesn't simplify (measured), dropping parts
  under a pixel never moves a vertex, and a prefix costs no memory.
- **One proxy per cell, no tree.** The far ring merges to about 650 slots at 320 m (measured). A
  tree pays off past the loaded rings, which are out of scope.
- **Dirty by change ticks, not hooks.** Deltas, dressing and swaps all touch members.
- **Ground groups per root, and region meshes, are opt-ins** that `hlodPlugin` sets (as built).
  Existing tests and tools count chunk meshes and one ground group; flipping the defaults can follow
  once 0116's numbers are re-measured.
- **Bytes are identical between builds, but proxies never enter a world hash.**

## Acceptance criteria

Fixture: `test/DressedTownCell` (`hlod/src/fixtures/dressed-town.ts`): 0116's street town in Risen's
shape. Fragments carry no render handles; a client system dresses trim, a mailbox and (full only) a
sofa with boxes and runtime materials after commit. Houses have a door and three windows at both
levels, and an inner wall at `full`. 64 m cells, `full` to 96 m and `far` (proxy) to 320 m. With
`rows: 1, gap: 18` (the scenario) it has Risen's density: 158 houses in 79 far cells. Budgets are in
`bench/perf/budgets.json`.

- [x] **Frame.** `town-hlod` (`hlod/src/scenario.test.ts`): a run along the street at 6 m/s in
      third person, a sun with four on-change cascades, occlusion on, 1920×1080 under `pnpm bench`.
      It meets the frame budget (CPU 16.7, GPU 16.6 ms on the laptop) and prints slots, draws and
      ms per ring. Not yet: the laptop itself, and Risen's town through a `shard capture` plan
      (it needs Risen's changes above).
- [x] **Budgeted builds.** Over the walk, `hlod/select` meets `hlod/frame` at p95 and
      `hlod/frame-max` at worst, and builds meet `hlod/build` at p95 (`scenario.test.ts`).
- [x] **A broken wall.** A wall in a covered far cell despawns, as a client's `applyCellDelta`
      removes it: its proxy is rebuilt within `hlod/rebuild-latency`, with fewer triangles;
      exactly one build runs, every other proxy stays, and the cell is covered on every frame
      (`hlod.test.ts`). Not yet: the same through `netHarness`.
- [x] **Coverage.** Walking ±48 m along the street for 60 s (3,600 frames), cells swapping levels
      throughout: every loaded cell draws exactly once on every frame, checked by slots (a covered
      cell's meshes hold none and its proxy's do; an uncovered cell's proxy holds none)
      (`hlod.test.ts`). Not yet: hole detection against the sky colour.
- [x] **Only windows swap, shadows included.** From the street, with a sun casting, the frame with
      proxies against the same frame with shells changes only inside the shells' window panes
      (dilated 1 px): at most 0.5% of pixels outside them (`hlod.test.ts`).
- [ ] **Shadows, by layer.** Static cascade layers with the cell and with its proxy bit-identical
      outside the house footprints. Covered for now by the frame comparison above.
- [x] **On the worker pool.** Proxies built on a Node pool through procgen's worker bundle match
      inline builds cell for cell (`hlod.test.ts`).
- [x] **Region meshes.** On structure's 60-building town, region meshes are at most 0.3× the chunk
      meshes (`structure/region-batches`), the frame matches per-chunk drawing within 0.1% of
      pixels, a wall edit rebuilds only the regions of its chunks, and turning regions off brings
      every chunk mesh back (`structure/src/region-meshes.test.ts`).
- [ ] **Occlusion pays.** With proxies and region meshes, the frame with occlusion no slower than
      without. Not measured yet: the scenario runs with occlusion on.
- [x] **Baseline.** Every HLOD and region-mesh test passes with `SHARD_TIER=baseline`. Not yet: the
      fake GL context, and the fixture on `?backend=webgl2` in the browser tests.
- [x] **Headless.** `hlodPlugin` needs `render/forward`, so a server or `shard run` can't build
      proxies, and their hashes don't change.

Part 2, file cells, once 0072's importer loads them, on 0072's fixture (2,000 building entities):

- [ ] **Offline build.** Editing one cell file rebuilds exactly that cell's record; the whole
      fixture builds within `hlod/offline-build`; two builds give identical mesh bytes and baked
      textures match within 0062's tolerance across Dawn on Metal and WARP; a file cell's runtime
      `merged` rebuild matches its offline record byte for byte.
- [ ] **Baked quality.** Across 20 cells, `hlod.preview` at the swap distance is within 0062's
      tolerance. A material with a custom fragment hook bakes to the colour it renders in a frame.
      Proxy texture memory stays under `hlod/texture-memory`.
- [ ] **No GPU.** With no adapter, `baked` cells fail with `hlod/no-gpu` and the `merged` ones
      build. `shard export` fails with `hlod/missing` while a record is missing.

## As built

Measured on an Apple M5 Max (not a named machine), 2026-11-13, Node Dawn on Metal, 1920×1080, the
`town-hlod` scenario under `pnpm bench` with the laptop's budgets:

| | Slots | Camera draws | CPU ms (median, standing) |
|---|---|---|---|
| Before: far cells as shells, structure as chunk meshes | 11,286 | 7,425 | 11.71 |
| With proxies and region meshes | 1,285 | 729 | 1.78 |
| Full ring (16 cells, 32 houses) | 632 | 234 | 0.48 |
| Far ring (79 proxies, 158 houses) | 653 | 495 | 0.49 |
| The rest (sky, lights, fixed costs) | 0 | 0 | 0.81 |

- The run: CPU frame p95 3.29 ms, GPU 1.31 ms. `hlod/select` 0.053 ms p95, 0.27 ms at worst; 85
  builds, 1.16 ms p95 and 2.30 ms at most each (inline: the time one takes on a worker).
- A broken wall's proxy is replaced within `settleFrames` + 4 frames (about 100 ms).
- `budgets.json`'s `town-hlod` shares are this run's, rounded up. Neither named machine has run
  it; the laptop's frame budget is the target Risen asked for.
- A bug on the way: `compute-visibility` resolved a tagged entity's own `Visibility` against its
  parent, so a proxy parked under a visible parent kept its slots. It resolves against the tag now.
- The structure test "hiding a level or a roof…" fails under `SHARD_TIER=baseline` on main as well
  (instance bytes 1,664 against 960); it isn't this spec's.

## Open questions

- **Past the last ring.** Proxies kept for unloaded cells would show a horizon, but the server sends
  no deltas there, so they'd go stale. Deferred: a game asking for view distances past ~500 m.
- **The laptop and Risen.** Proposed: run `town-hlod` on the laptop, and Risen's town through a
  capture plan once Risen has the changes above, before marking this implemented.
- **One draw per proxy.** A per-vertex material index (0055's open question) if the laptop still
  misses its budget. Proposed: after measuring.
- **Coarser layers for file cells** (0073's old tree of 4 × 4 and 16 × 16 blocks). These only pay
  off past the loaded rings, so they follow the first question.
- **Region meshes and ground groups by default.** Proposed: yes, in the change that re-measures
  0116's numbers with them.
