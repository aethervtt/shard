# 0073 — Hierarchical LOD (HLOD)

- **Status:** accepted
- **Packages:** `@aethervtt/shard-hlod` (new), `@aethervtt/shard-partition`, `@aethervtt/shard-mesh`,
  `@aethervtt/shard-render`, `apps/cli`
- **Depends on:** 0014, 0020, 0021, 0022, 0042, 0045, 0062, 0072

## Context

With 0072, nothing exists beyond a cell's load range. From a hilltop the town 2 km away is
missing, along with the castle on the far ridge and the bridge over the valley. Raising the load
range brings them back, but every loaded cell costs memory and spawn time, and its hundreds of
entities draw separately, so draw calls grow with the square of the range. Per-mesh LOD (0022)
makes each mesh cheaper but doesn't reduce the number of meshes.

HLOD bakes a group of cells into one cheap stand-in, a **proxy**: a merged, simplified mesh,
usually with a single material whose textures are baked from the originals. A proxy draws while
its cells are unloaded. Proxies form a tree: one per cell nearby, one per block of cells farther
out, and so on, so the draws needed for the horizon stay roughly constant.

Proxies are derived data. They're built from the cell files by a CLI step, stored in the cache,
and rebuilt when a cell changes, like 0071's terrain pages.

## Goals

- HLOD layers per partition grid, each with a block size in cells, a distance range, a method and
  a quality target.
- Three methods: `instances` (the cells' meshes at their last LOD, instanced, with no geometry
  bake), `merged` (meshes merged per material and simplified, original materials kept), and
  `baked` (everything merged into one simplified mesh with one baked material).
- Baking that works for any 0020 material, including custom hooks, with no per-material code.
- Incremental builds keyed by content. Editing one cell rebuilds that cell's proxies and their
  ancestors, and nothing else.
- Swaps between a cell and its proxy, or a proxy and its parent, happen in one frame, with no
  hole and no double draw.
- Proxies stream: only those within range plus a margin are loaded.
- Agents can measure a proxy's quality against the real thing.

## Non-goals

- Terrain. 0071's terrain has its own LOD and streams independently of cells.
- Scatter and foliage (0045). They're procedural and ranged, and imposters are 0045's open
  question.
- Lights. A cell's point lights go out with the cell. Baked glow for distant windows is an open
  question.
- Animated, skinned, transparent and dynamic-body entities. They aren't included in proxies.
- Dithered crossfades between a cell and its proxy. Swaps are instant, as 0022's LOD switches are.

## Design

### Settings

```json
{
  "grids": [
    { "name": "main", "cellSize": 128, "loadRange": 384,
      "hlod": [
        { "cells": 1, "method": "merged", "range": 1200, "errorPixels": 2 },
        { "cells": 4, "method": "baked", "range": 5000, "errorPixels": 3, "texelsPerMetre": 2 },
        { "cells": 16, "method": "baked", "range": "infinite", "errorPixels": 4, "texelsPerMetre": 0.5 }
      ] }
  ]
}
```

- Layer k's nodes each cover `cells × cells` grid cells, aligned to multiples of `cells`. Each
  layer's `cells` is a multiple of the previous layer's. Layer 0 draws from the grid's
  `loadRange` to its `range`, layer 1 from there to its own `range`, and so on. The last layer may
  be `"infinite"`.
- `errorPixels` sets the simplifier's error in metres, so that at the layer's nearest distance
  the error projects to that many pixels on a 1080p view at 60° field of view.
  `texelsPerMetre` sets the baked atlas size.
- **Members.** A root entity in a cell is in its proxies if its subtree draws an opaque or masked
  `Mesh3d` and has no `Animator`, skin, dynamic or kinematic body, or `hlod/Exclude` tag. Its
  subtree's meshes are included as they're posed in the file. Prefab and scene instances are
  expanded. A mesh with `Lod` contributes its last level (`instances`, `merged`) or its first
  (`baked`, which simplifies on its own).

### Methods

- **`instances`**: the proxy is a list of `(mesh, material, transform)` per batch, drawn as GPU
  instance batches through 0022 with no entities. It's cheapest to build and best for repeated
  kit pieces (fences, walls, lamp posts), and it leaves the draw count per batch at one.
- **`merged`**: meshes are merged per material in the node's frame and simplified with
  meshoptimizer to the layer's error, borders locked so neighbouring nodes don't crack. Original
  materials and UVs are kept, so the draw count is the number of materials.
- **`baked`**: everything is merged, simplified, given a fresh UV atlas, and its surface is baked
  into base colour, normal and ORM textures. That's one mesh and one material per node.

`simplifyLods` comes from 0045's mesh toolkit. If 0045 hasn't landed, this spec builds that
function. Atlas UVs come from xatlas (WASM), loaded with `import()` by the build only. Neither
reaches a runtime bundle.

### Baking surfaces

The bake reuses the deferred path (0021) instead of evaluating materials itself:

1. Render the node's member entities, at full detail with their own materials, into G-buffers
   from 14 orthographic directions (the 6 axes and 8 corners), sized by `texelsPerMetre`. Any
   0020 material, hooks included, writes the G-buffer as it would in a frame.
2. For each atlas texel of the simplified mesh, take its position and normal, project it into
   every view, keep the views where it's visible (its depth matches within the simplifier's
   error), and blend them, weighting each by how directly it faces the normal.
3. Write base colour and ORM directly. Normals are stored in object space, which suits a static
   proxy and avoids tangent frames on a remeshed surface. Dilate every texture by 4 texels.

The proxy uses a dedicated `hlod/Proxy` material (base colour, object-space normal, ORM), so it's
lit dynamically and casts shadows like everything else. Texels that no view sees take the
nearest seen texel's value.

### Build and storage

- A node's key is `sha256(layer settings, the member data of its cells (component values,
  canonical), the artifact hashes of their meshes, materials and textures, the bake version)`.
  Cells with no members contribute nothing, so an empty field costs no rebuild.
- `shard hlod build [partition]` builds stale nodes, finest layer first, on the worker pool for
  merging and simplifying and on the GPU for baking (Dawn in Node). `--layer` and `--cells`
  limit it. Each node is one record in `.shard/cache/hlod/<partition hash>/`: the mesh
  (0014's codec), the textures (KTX2), its bounds, and the hash of every cell it covers.
- `shard dev` rebuilds stale nodes in the background after a cell is saved. A stale proxy keeps
  drawing until its replacement is ready. `shard export` builds everything and fails with
  `hlod/missing` if a node can't be built.
- `baked` needs a GPU adapter. Without one, the build fails for those layers with `hlod/no-gpu`
  and builds the others. CI's software GPU is enough.

### Runtime

- The partition (0072) owns an HLOD tree per grid: layer-0 nodes over cells, and each higher
  node over the nodes below it. Each frame that the cell selection changes, it decides what
  covers every region within the last layer's range:
  - a **cell** covers itself once it's spawned;
  - a **layer-0 node** draws when its cells aren't all spawned, its proxy is loaded, and the
    camera is within its range;
  - a **higher node** draws instead of its children when all of them would draw as proxies (none
    are spawned cells), the camera is beyond the range of the layer below, and its proxy is loaded.
- A node whose replacement isn't ready keeps drawing. A spawning cell hides its layer-0 proxy in
  the frame it spawns, through the same command batch. Coverage is therefore exact on every
  frame: each region draws once, never zero or two times.
- Proxies are entities (a few thousand at most), children of the partition root with `GridCell`,
  marked `core/Derived`, with no physics. Their meshes and textures are virtual assets (0042's
  `gen:` store), so 0014's reachability unloads them. Nodes within 1.25 × their range are loaded,
  nearest first, sharing 0072's `readsInFlight`. The last layer stays resident.
- Shadows: proxies cast shadows into cascades past the loaded cells, and cascades over loaded
  cells use the cells themselves.
- Headless runs neither load nor draw proxies, so world hashes are unaffected.

### Agent surface

- `hlod.describe { partition }`: layers, nodes built, stale and missing, proxies drawn per layer,
  triangles and draws for proxies against what the covered cells would draw, and texture memory.
- `hlod.preview { node, distance? }`: renders the node's cells and its proxy from the same
  viewpoint at the layer's nearest distance and returns both images and their 0062 comparison
  (deltaE). An agent can check a proxy without flying anywhere.
- `render.capture { debug: 'hlod' }` tints proxies by layer and leaves real cells untinted.
- `shard hlod build` and `shard hlod status` (stale nodes and why: which cell or asset changed).
- MCP tools: `describe_hlod`, `preview_hlod`, `build_hlod`.
- **Errors:** `hlod/no-gpu`, `hlod/missing`, `hlod/bad-layers` (a layer's `cells` isn't a
  multiple of the previous one, or ranges don't increase), `hlod/too-big` (a node whose atlas
  would exceed 4 096² at its `texelsPerMetre`; the message suggests a smaller block or density).

## Decisions

- **Proxies are derived and cached, never committed.** They're a function of the cell files, and
  a key per node rebuilds exactly what changed.
- **Projection baking through the G-buffer.** Every material, custom hooks included, bakes
  correctly with no material-specific code. Concave spots no view can see are the cost, and they
  hardly show at proxy distances.
- **Object-space normals.** A remeshed, static proxy has no meaningful tangent frame.
- **Three methods, chosen per layer.** Near layers want the original materials (`merged`) or
  just fewer draws (`instances`), and far layers want one draw (`baked`).
- **Instant, exact swaps.** Coverage is a rule over ready states, so holes and z-fighting can't
  happen. Crossfades can come later with 0022's.
- **No terrain HLOD.** Unlike Unreal's Landscape, 0071's terrain doesn't stream by cell, so it
  needs no stand-in.

## Acceptance criteria

- [ ] On 0072's fixture with a town of 2 000 building entities, a view from 2 km away draws the
      town in under 40 draws, and its 0062 comparison against the same view with every cell
      loaded is within the default tolerance.
- [ ] Each layer's proxies are within `errorPixels` of the originals at their nearest distance,
      measured by `hlod.preview` across 20 nodes.
- [ ] Flying across the fixture at 100 m/s, every frame covers each region exactly once. That's
      checked logically each frame, and by hole detection against the sky colour.
- [ ] Editing one cell file rebuilds exactly that cell's layer-0 node and one node per higher
      layer (count asserted). Building the whole fixture takes under 10 minutes on the desktop
      (budget `hlod/build`, proposed).
- [ ] Two builds of the fixture produce identical proxy mesh bytes. Baked textures match within
      0062's tolerance across Dawn on Metal and WARP.
- [ ] A material with a custom fragment hook bakes to the colour it renders in a frame, within
      0062's tolerance from the layer's nearest distance.
- [ ] HLOD adds at most 1 ms of main-thread time a frame (p95) during the flight. Proxy texture
      memory stays under 256 MB.
- [ ] `shard run` world hashes are identical with and without built proxies.

## Open questions

- Answered: `baked` captures emissive (it's in the G-buffer). Deferred: glow cards for distant
  point lights.
- Deferred: making `instances` the default for layer 0, until its draw count is measured on the
  fixture.
