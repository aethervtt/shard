# 0012 — Headless CLI

- **Status:** implemented
- **Packages:** `apps/cli` (`shard` binary), `@shard/testing`
- **Depends on:** 0009, 0010, 0011

## Context

The CLI is the agent's main tool when there's no window: create a project, validate it, run it for
N frames, take a screenshot, run gameplay tests, regenerate docs. Every command has to be
scriptable: machine-readable output, meaningful exit codes, no prompts.

## Goals

- Commands: `init`, `validate`, `run`, `screenshot`, `test`, `describe`, `docs`, `serve`.
- Headless rendering through Dawn (0005), so screenshots work with no window or browser.
- `--json` on every command, exit codes that mean something.
- A small gameplay-test API: a headless app, steps, input injection, assertions on world state and
  screenshots.

## Non-goals

- Export/packaging (M9).
- Interactive modes.

## Design

### Commands

```sh
shard init <dir> [--template empty|explorer]    # scaffold a project (0009)
shard validate [--json]                         # manifest, scenes, schemas; all errors
shard run [--frames 600] [--seed N] [--scene path] [--json]
shard screenshot <scene> --out shot.png [--size 1280x720] [--frames 60] [--camera path]
shard test [pattern] [--json]                   # runs tests/*.test.ts
shard describe [--json]                         # app.describe + registry + render + input
shard docs                                      # regenerates AGENTS.md block, .agents/, schemas
shard serve [--port 7811]                       # protocol hub: stdio + WebSocket (0011)
```

- Project code (`entry`) loads through Vite's module runner, so TypeScript and `@shard/*` imports
  work without a build step.
- Exit codes: 0 success, 1 validation or test failure, 2 runtime error (with the `ShardError`
  printed), 3 usage error.
- `--json` prints one JSON document to stdout; human output goes to stderr, so pipes stay clean.

### Gameplay tests

```ts
// tests/ship.test.ts
import { test, expect } from '@shard/testing'

test('the ship lifts off when thrust is held', async ({ game }) => {
  await game.load('scenes/main.scene.json')
  game.input.hold('ship/Controls.thrust')
  await game.step(120)
  expect(game.entity('ship').get('core/Transform').translation[1]).toBeGreaterThan(5)
  await game.screenshot('liftoff.png') // saved next to the test results
})
```

`@shard/testing` wraps a headless app with the project loaded, fixed delta, fixed seed, and the
protocol methods as a typed API. It runs on Vitest, so failures print normally and agents can read
them.

### Screenshots

`screenshot` loads the scene, runs `--frames` (so things settle), captures the chosen camera's view
through Dawn, and writes a PNG. Offscreen size comes from `--size` or the manifest's window.

## Decisions

- **Vite module runner for project code.** Already a dependency; handles TS and workspace imports.
- **stdout for data, stderr for humans.** Agents parse without scraping.
- **Tests on Vitest.** Familiar output, and the engine's own tests already use it.
- **Workspace app until M9.** Published as an npm binary (`npx shard`) with export/packaging.

## Acceptance criteria

- [x] `shard init` then `shard validate` passes on the new project; a broken scene makes `validate`
      exit 1 with every error listed.
- [x] `shard run --frames 600 --seed 1 --json` is deterministic (same world hash across runs).
- [x] `shard screenshot` writes a PNG matching a golden image, with no window or browser.
- [x] `shard test` runs a sample gameplay test with input and a screenshot, and reports failures
      with exit code 1.
- [x] `shard docs` regenerates docs from the project's registry (0009 criteria).
- [x] Every command supports `--json` and uses the documented exit codes.

## Implementation notes

- **Project code loads through `tsx`, not Vite's module runner.** The `shard` bin registers the tsx
  loader, so `entry`, tests, and `@shard/*` workspace imports run as TypeScript in plain Node. The
  module runner needed a Vite dev server spun up inside every command.
- **Two extra commands:** `shard mcp` (0013) and `shard serve`, which runs the hub over WebSocket
  and stdio at once.
- **Testing API as built:** `game.get(entity, component)` is synchronous and returns JSON
  (`game.get('ship', 'core/Transform').translation[2]`). `game.entity(id)`, `game.patch`,
  `game.call(method, params)`, and `game.input.hold/release/press` cover the rest. Tests share one
  Dawn device per worker. `shard test` runs Vitest with `SHARD_PROJECT_ROOT` set.
- **Numeric flags** are validated (`--frames abc` is a usage error, exit 3). `--seed` overrides the
  manifest's seed.
