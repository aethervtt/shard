# 0036 — UI and HUD

- **Status:** implemented
- **Packages:** `@shard/ui` (new), `@shard/input`, `@shard/render`, `@shard/platform`,
  `@shard/platform-web`, `@shard/project`, `@shard/testing`
- **Depends on:** 0008, 0024, 0025, 0030

## Context

The proof project needs a HUD (fuel, speed, a scanner readout), markers over planets and points
of interest, an inventory grid, and menus. VISION calls for engine-rendered, retained UI with
flexbox layout, so a game looks the same on every export and UI is data like everything else.

For an agent, the key property is that UI is inspectable. It should be able to ask "where is the
fuel bar and what does it say" and get rectangles and strings back, and it should be able to
press a button by name. Screenshots are for checking that it looks right, not for finding things.

## Goals

- UI as entities: `UiNode` with flexbox layout (direction, wrap, justify, align, gap, padding,
  margin, sizes in px, %, auto, and flex grow and shrink), absolute positioning, and z-order.
- Visuals: background color, border (width, color, radius), images (texture or atlas region,
  nine-slice), MSDF text with wrapping and alignment, and clipping with scroll.
- Interaction: hover, press, and click from mouse, touch, and gamepad or keyboard navigation with
  focus; `UiButton`, `UiToggle`, `UiSlider`, and `UiTextInput`.
- Themes as data assets: named styles that nodes reference, hot reloaded.
- World-anchored UI: nodes that follow an entity's screen position, with clamping to screen edges
  (planet markers), and scale-by-distance options.
- UI authored in prefabs and scenes (a HUD is a prefab), and driven by systems that write text and
  sizes.
- Layout of 2,000 nodes in under 1 ms, and nothing relayouts on a frame where nothing changed.

## Non-goals

- A CSS parser or HTML. Styles are component fields and theme files.
- Rich text beyond color and size spans. Right-to-left text and complex shaping (0025's limits).
- Animated transitions beyond what property clips (0032) do to UI fields.
- UI rendered into 3D world space as meshes (later: render a UI tree to a texture).

## Design

### Components

```ts
UiNode {
  display: 'flex' | 'none', position: 'relative' | 'absolute'
  direction: 'row' | 'column' | 'row-reverse' | 'column-reverse', wrap: bool
  justify: 'start' | 'center' | 'end' | 'space-between' | 'space-around' | 'space-evenly'
  alignItems / alignSelf: 'stretch' | 'start' | 'center' | 'end'
  width, height, minWidth, maxWidth, minHeight, maxHeight: length   // "120", "50%", "auto"
  left, top, right, bottom: length, padding, margin: vec4 (px), gap: vec2
  grow: f32, shrink: f32 = 1, basis: length, order: i16, zIndex: i16
  overflow: 'visible' | 'clip' | 'scroll', style: string (theme style name)
}
UiStyle { background: color, borderColor: color, borderWidth: f32, radius: vec4, opacity: f32 = 1 }
UiText { text: string, key: string (localization, 0038), size: f32 = 16, color: color,
         font: handle('Font'), align: 'start' | 'center' | 'end', wrap: bool = true }
UiImage { texture: handle('Texture'), atlas: handle('TextureAtlas'), region: string,
          slice: vec4 (nine-slice borders in px), tint: color, fit: 'fill' | 'contain' | 'cover' }
UiButton { disabled }  UiToggle { on, disabled }
UiSlider { value: f32, min: f32, max: f32 = 1, step: f32, fill: color, disabled }
UiTextInput { value: string, placeholder: string, maxLength: u16, disabled }   // shown via its UiText
UiInteraction { state: 'none' | 'hovered' | 'pressed' | 'disabled', focused: bool }   // readonly
UiAnchor { target: entity, offset: vec3 (world), screenOffset: vec2, pivot: vec2 = [0.5, 0.5],
           clamp: bool, margin: f32 = 16, hideBehind: bool,
           scaleDistance: f32 (0: off), minScale: f32 = 0.5, maxScale: f32 = 1.5 }
UiAnchorArrow (tag)
UiRoot { scale: 'none' | 'fit-height' | 'fit-width', referenceSize: vec2 = [1920, 1080],
         camera: entity, theme: handle('UiTheme'), order: i16 }
UiDefaults (resource) { font }   // text with no font and no theme font
```

- A UI tree is entities under a `UiRoot`, ordered by `ChildOf` and `order`. `Transform` isn't used
  for layout; the computed rect is in `UiLayout { x, y, width, height, clip, content, scale, angle,
  visible, anchor, distance }` (readonly, not serialized, in pixels of the root's reference size;
  `clip` is the visible part of the node, `content` the scrollable extent, `anchor` and `distance`
  the anchor state). The root always fills the screen.
- `length` fields (`uiLength()`, field kind `length` in core) take a number (pixels), `"120"`,
  `"120px"`, `"50%"`, or `"auto"` in JSON; a read gives a number for pixels and a string otherwise.
  They're one f32 column with two floats per row (value, unit), so layout reads TypedArrays.
- Borders draw inside the box and take no layout space.

### Layout

- A TypeScript flexbox implementation of the subset above (`flex.ts`, over TypedArrays), run in
  `PostUpdate` after transform propagation (anchors need world positions). A changed UiNode,
  image, root, viewport, theme, or font dirties its root, and only dirty roots relayout. A text
  change dirties it only when the measured string, font, size, line height, or wrap changed, so
  writing the same text each frame is free. Text measures with 0025's layout; lines are
  `lineHeight × size` tall with the glyphs centered in them (half-leading, as CSS does).
- Differences from a browser, on purpose: a flex item's automatic minimum size is its min-content
  size only for text and image leaves (containers shrink down to their padding), there's no
  `align-content` (lines stretch, CSS's default), and there are no auto margins.
- Anchored nodes are positioned by layout: absolute, their `pivot` on the target's projected
  point, ignoring the parent's position. The projection uses the root's camera (Camera3d and its
  GlobalTransform), so it works headless. `clamp` keeps them `margin` from the edges (a target
  behind the camera clamps to its side); `hideBehind` hides them while it's behind; without clamp,
  behind means hidden. A frame where only anchor points moved repositions (no layout).
  `scaleDistance` scales the node and its subtree by `scaleDistance / distance`, clamped. A
  `UiAnchorArrow` child shows only while clamped, placed just outside the node's edge toward the
  target and rotated to point at it.

### Rendering

- One overlay pass after tonemapping (phase Overlay + 20, after screen sprites and screen text).
  Nodes emit quads (rounded rects with borders via SDF in the fragment stage), images (fill,
  contain, cover, or nine-sliced into 9 quads), slider fills, MSDF glyph quads, and a caret for a
  focused field into one storage buffer, in paint order (tree order, siblings by `zIndex`, roots
  by `order`), batched by texture: boxes join any batch. Opacity multiplies down the tree.
- Clipping is a per-quad clip rect tested in the fragment stage rather than scissor rects, so a
  clip node doesn't break batches and nested clips are just intersections.
- The buffer is rebuilt and uploaded only on frames where a root's layout or look changed
  (describe counts `rebuilds` and `uploadedBytes`); otherwise nothing uploads.

### Interaction

- `ui/interact` runs in `First` between `input/update` (devices) and `input/actions` (action maps,
  split out of the old single system for this). It hit-tests last frame's rects top-down against
  clipping. A node takes the pointer when it's a widget, has an image, scrolls, or has a visible
  background or border (from itself or its theme); text alone doesn't. The widget is the hit
  node or its nearest interactive ancestor.
- While the pointer is over UI (or a press that started on a widget is held), `Mouse.captured`
  is set and action maps read mouse buttons and the wheel as released; touches that start on UI
  go in `Touches.captured`. World picks (0027) at a pixel UI takes resolve to nothing through a
  `PickBlocker` render registers. So clicking a HUD button doesn't shoot.
- A click is press and release on the same widget; dragging a slider sets its value; the wheel
  scrolls the nearest `overflow: scroll` node.
- Focus: Tab and Shift+Tab move through widgets in tree order. Once something has focus, arrow
  keys and the D-pad move to the nearest widget in that direction (left and right step a focused
  slider). Enter, Space, or south activates; Escape or east drops focus. Only text fields take
  focus from the pointer (a HUD button clicked with the mouse doesn't steal the keyboard);
  `focusUi` / `ui.focus` gives it from code.
- Typing: a new raw event `{ type: 'text', text }` carries typed characters (repeats included,
  `"\b"` for backspace) from the DOM source into `Keyboard.typed`; a focused field edits from it.
- Events: `UiClick { entity }`, `UiChanged { entity }` (toggle, slider, input), `UiHover { entity,
  hovered }`.
- Input maps listen in a context (`defineActions(name, def, { context })`, default `game`, or
  `any`); the `InputContext` resource says which is active, and UI makes it `ui` while a node has
  focus, so gameplay actions don't fire while typing or navigating a menu.

### Themes

`*.theme.json` data assets (`{ font, styles }`) map style names to `UiStyle` and `UiText` fields
(not `text` or `key`) plus state variants (`button:on`, `:focused`, `:hovered`, `:pressed`,
`:disabled`, applied over the base in that order). Style fields are validated and converted with
those components' own field types, so a theme takes exactly what a node does. `UiNode.style`
names a style; an entity field that differs from its default wins over the theme (so a field at
its default takes the theme's value). A `UiRoot` picks its theme with `theme: handle('UiTheme')`.
Text measures with the base style (state variants shouldn't change sizes). Hot reload updates the
theme in place and bumps its version, which restyles and relays out its roots.

### Agent surface

- `ui.describe { root? }`: the tree with names, paths, computed rects, text, style, widget kind
  and state, focus, anchor state and distance, scroll, and this frame's work (`layouts`,
  `nodesLaidOut`, `repositions`, and the renderer's `rebuilds` and `uploadedBytes`). Agents check
  layout and read the HUD as data.
- `ui.click { entity }` and `ui.focus { entity }` drive UI by id or path (a unique suffix like
  `"play"` works) from tests and MCP (`ui_describe`, `ui_click`, `ui_focus`), without pixel
  coordinates. Gameplay tests get `game.ui.describe()`, `node(path)`, `click(path)`, `focus(path)`.
- The `ui-layout` overlay outlines node rects with padding and margin.
- A skill, `make-a-hud.md`: a HUD prefab, binding text from a system, anchoring a marker, testing
  a button with `ui.click`.
- **Errors:** `ui/invalid-length`, `ui/no-root` (a UiNode outside any UiRoot) and
  `ui/unknown-style` (logged once as warnings), `ui/unknown-state` (a theme style state),
  `ui/unknown-node`, `ui/ambiguous-path`, `ui/not-clickable`, `ui/not-focusable`, `ui/disabled`,
  `ui/hidden`.

## Decisions

- **Our own flexbox subset.** Yoga and Taffy are full implementations, but they'd add WASM and a
  second tree to keep in sync with the ECS. The subset games use is a few hundred lines that lay
  out columns directly.
- **Layout results are components.** `UiLayout` makes UI state readable through `entity.get` and
  gameplay tests like any other data.
- **UI trees are prefabs.** No second authoring format, and overrides and variants work for UI.
- **Pointer goes to UI first.** The common bug, clicks passing through HUD into the world, is
  solved once in the engine: action maps and world picks both skip what UI takes.
- **Layout places anchors.** Writing `left`/`top` before layout would need the node's size to
  apply a pivot, and would relayout every frame the camera moves; placing them in layout keeps
  pivots exact and lets a moving marker reposition without a layout.

## Acceptance criteria

- [x] Flexbox fixtures (row, column, wrap, grow and shrink, justify and align variants, absolute,
      percent sizes, min and max) lay out to the same rects as a browser for the same styles
      (fixtures checked in with rects measured in Chrome).
- [x] A HUD prefab renders as a golden image: rounded bordered panels, nine-slice image, wrapped
      text, clipped scroll area.
- [x] A world-anchored marker tracks an entity, clamps to the screen edge when it's behind the
      camera, and hides with `hideBehind`.
- [x] `ui.click` on a button path sends `UiClick`, and a real pointer click on it doesn't reach
      world picking.
- [x] Gamepad navigation moves focus in all four directions through a 3×3 grid.
- [x] 2,000 nodes lay out in under 1 ms, and an unchanged frame does no layout and no upload
      (describe counts).
- [x] Editing a theme file restyles a running UI.

Covered by tests in `packages/ui`: `flex.test.ts` (26 cases measured in Chrome 153 by
`fixtures/gen-flex.html`), `render.test.ts` (the HUD golden, uploads, picks, overlay),
`ui.test.ts` (ECS layout and counts, pointer, `ui.click`, the 3×3 grid, text fields, sliders,
scroll, anchors, themes, 2,001 nodes in 0.84 ms under `pnpm bench`), and `theme.test.ts` (a
theme file edited on disk, reimported by the asset server).
