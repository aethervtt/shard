# 0025 — Text rendering (MSDF)

- **Status:** accepted
- **Packages:** `@shard/text` (new), `@shard/render`, `@shard/assets`
- **Depends on:** 0014, 0016, 0024

## Context

Nothing in the engine can draw a letter yet. Games need text in the world (a planet's name over
its scanner marker, signs, damage numbers) and on screen (the HUD in M6 builds on this). Text has
to stay sharp at any size and angle, lay out correctly (kerning, line breaks, alignment), and be
cheap enough to change every frame.

Multi-channel signed distance fields (MSDF) keep sharp corners at any scale from one small atlas.
They're generated at import, so runtime text costs one texture and instanced quads.

## Goals

- A font importer (`.ttf`, `.otf`) that generates an MSDF glyph atlas and metrics at import, for a
  configurable character set.
- `Text` for world-space text and `ScreenText` for overlay text, with size, color, alignment, line
  height, max width, and wrapping.
- Layout: advances, kerning pairs, line breaking at spaces and CJK boundaries, and alignment.
  Measurement is available without rendering.
- Styling: outline, soft shadow or glow, and weight adjustment, all from the distance field without
  extra textures.
- Fallback fonts for missing glyphs, and on-demand atlas pages for glyphs outside the imported set.

## Non-goals

- Complex script shaping: Arabic joining, Indic reordering, bidi (later, through a shaping library).
- Rich text markup beyond per-span color and size (M6 UI).
- Bitmap fonts (use sprites).
- Colored emoji (later).

## Design

### Import

- The `font` importer parses the font (the `opentype.js` parser) and generates an MSDF per glyph
  in TypeScript: edge coloring, per-channel signed distance, error correction (a port of msdfgen's
  core). Glyphs are packed into an RGB atlas (KTX2 via 0016, linear, no mips).
- Settings: `charset` (latin, latin-extended, custom string), `size` (em size in atlas pixels,
  default 48), `range` (distance range in pixels, default 4), `fallback` (font paths), `kerning`.
- Artifacts: the atlas texture sub-asset (`#Atlas`) plus metrics JSON (per glyph: advance,
  bearings, atlas rect; font ascent, descent, line gap, and kerning pairs).
- Glyphs outside the charset: when a string needs one, it's generated at runtime into an extra
  atlas page (the same code runs in the browser), cached, and reported in `render.describe`.

### Components

```ts
Text {
  value: string
  font: handle('Font')
  size: f32                    // world units (meters) per em
  color: color
  align: 'left' | 'center' | 'right'
  anchor: vec2                 // pivot of the text block
  maxWidth: f32                // 0 = no wrapping
  lineHeight: f32 = 1.2        // multiple of the em size
  outline: { width: f32, color }, shadow: { offset: vec2, softness: f32, color }
  billboard: bool              // face the camera (markers, labels)
}
ScreenText { ...Text, size in pixels, position in screen space (anchors to viewport corners) }
```

- Layout runs when `value`, font, size, or width changes (change detection), and stores glyph
  instances. Unchanged text doesn't lay out again.
- `measureText(world, font, value, options)` returns the width, height, and line breaks, for UI
  and agents.

### Rendering

- Glyphs render as instanced quads in the sprite pass pattern (0024): world text sorted with
  transparent geometry, screen text after tonemapping.
- The MSDF shader takes the median of the three channels, uses a screen-space derivative for
  anti-aliasing (sharp at any scale), and applies the outline and shadow as distance offsets.
- sRGB-correct blending, with coverage on premultiplied color.

### Agent surface

- `asset.preview` of a font renders a specimen (the charset at several sizes).
- `measure_text` is a protocol method and MCP tool, so an agent can size labels before placing
  them.
- `render.describe` reports text entities, glyph count, atlas pages, and missing-glyph fallbacks.

## Decisions

- **MSDF, generated at import in TypeScript.** It's sharp at any size from one small atlas. Doing
  it in TypeScript keeps importers identical on every host (0014), and the runtime fallback for
  missing glyphs uses the same code.
- **Layout without shaping in v1.** Kerning and line breaking cover Latin, Cyrillic, Greek, and CJK
  display text, which is what the proof project needs. Shaping comes with the scripts that need it.
- **Style from the distance field.** Outlines, shadows, and glow cost a few instructions, not
  extra passes or textures.

## Acceptance criteria

- [ ] Importing a Latin font (about 400 glyphs) takes under 2 s. The atlas and metrics match the
      font's advances and kerning pairs for a set of test strings (widths within 0.5 px at 48 px).
- [ ] Text renders sharp at 8 px, 48 px, and 400 px, and at 60° to the camera (golden images).
      Outline and shadow render as configured.
- [ ] Line wrapping at `maxWidth` breaks at spaces and between CJK characters, and alignment is
      correct (layout tests without a GPU).
- [ ] A missing glyph uses the fallback font, or is generated at runtime into a new atlas page.
- [ ] 10k glyphs changing every frame (counters) cost under 2 ms of CPU time per frame.

## Open questions

- None blocking. Deferred: shaping through HarfBuzz (WASM) for complex scripts, and colored emoji.
